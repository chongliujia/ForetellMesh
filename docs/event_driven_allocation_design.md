# 低换手、事件驱动的模拟交易方向

2026-09-20 用户明确指出：预测市场策略不应过于频繁地交易。本页保留据此修正的设计方向。后续已按用户补充的“数天／数周”节奏完成 v2 实现和回放，见[事件持仓基线](event_allocation_baseline.md)；旧实验结果保持不变。

现有实现确实偏向短周期价格交易：每小时允许重新决策，最长计划持仓 48 小时，允许主动部分或全部平仓。`trading_rl_data.prepare` 还把最后一个研究观察点作为每份合约的 `retire_at`，环境在该边界发出 `scope_end` 卖出请求。观察点可能在事件发布前一天，甚至更早；它是数据集边界，不是合约实际停止交易或结算的时间。这种设计不适合直接验证长期事件判断带来的收益。

下一轮以低换手的事件判断策略为主，保留历史均值回归作为独立对照：

- 研究与风控可以持续更新；研究刷新或新小时到来本身不触发交易。
- 开仓依据应是有时间出处的事件判断与可执行价格之间的优势，扣除适用成本并考虑预测不确定性、资金占用和风险。历史价格均值不能代替结算概率。
- 建仓后允许跨多日持有，也允许在合适条件下持有至已核验结算；不沿用无条件的 48 小时退出作为主策略设计。
- 重新分配需有实质理由：新证据改变判断、市场价格已充分反映优势、继续持有相对卖出的优势消失，或触发明确风险限制。对继续持有与卖出的比较只计算各自未来相关成本，不再次收取沉没的建仓手续费。
- 买入与退出使用分别定义、事先冻结的阈值，避免同一边界附近反复开平仓；阈值尚未指定，不能从已看过的收益反推最优值。
- 低换手是成本与决策规则共同产生的行为，不设“每周必须交易一次”，也不把长期持仓本身加成训练奖励。无优势时允许长期持有现金。

实现必须先把研究观察截止、公开的事件日程、订单可提交区间、持仓跟踪区间、实际结算到账分开。真实结算时间和标签仅供模拟执行／评估使用，不能提前变成策略已知的未来时间。历史成交及报价覆盖不足的区间要显式保留缺失；不能用后来价格回填，也不能假设到研究截止点就必然能卖出。

先完成不训练的低换手基线，与现金及已有短周期基线在同一合格范围、相同成本条件下比较，再判断是否需要 RL。信号仍应来自冻结的真实 Agent 输出，遵守实际生成延迟、过期和失败缺失规则。没有可靠信号时，零交易是有效结果，不能为了展示持仓收益制造观点。

除了扣费净权益、回撤和执行可行性，报告持仓天数、换手、每个事件的开仓／退出次数、持有至结算比例，以及资金占用时间。所有退出保留明确原因，单独记录风险退出。降低频率可能减少执行损耗，但不能保证盈利，也不能替代预测优势和风险管理。
