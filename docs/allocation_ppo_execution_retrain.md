## 运行前固定的协议

[可执行配置](../configs/allocation_ppo_execution_retrain_v1.json)绑定前轮配置、结果及逐笔审计哈希，继而绑定原 PPO 权重、数据与执行源码。原[规划规格](../configs/allocation_rl_experiment_plan_v1.json)保留为历史设计稿。本轮没有新开发集，明确是训练内机制对照，未执行原计划中的新开发集验收。

- 训练订单有效期 **3,600 秒**，与每小时决策周期相等，避免在下一决策点遗留未被 88 项观测显式描述的挂单。4 小时仅作执行迁移压力检查，不根据结果选时长。
- 三个配对种子 **7 / 17 / 27**，主种子 7；每组各 **32,768 步**，两组共 **196,608 步**。使用原 PPO 超参数和主成本，不加训练预算或挑选 checkpoint。
- 两组从各自种子的原始随机初始化重新训练，逐张量哈希须与旧实验的 `initial.zip` 一致；不从旧的已训练参数继续训练。CPU 单线程、确定性算法，网络仍为 **21,402 参数 / 88 输入 / 25 动作**。
- `net_equity`：原有扣费净权益变化。`net_equity_cadence`：同一净权益变化减去 **每超期小时 $0.10** 的学习成本；该权重继承既有设计，未用本轮结果调参。
- 无换手奖励、持仓奖励或第二次手续费扣除。学习惩罚单列，永不改动模拟现金。
- 六个 checkpoint、优化器和训练记录全部冻结后，统一确定性回放 **2 个有效期 × 3 档成本 × 11 个策略 = 66 组**。11 个策略包括两条固定规则、三个旧 PPO、六个本轮 PPO。
- 始终报告所有种子、成本情景与周频验收。无论收益如何，本轮均不晋级默认，不打开验证输入/标签及最终测试。

## 超期成本与硬验收

每个无成交区间 `[a,b]`，上次实际买卖成交（或回放起点）为 `L`：

```text
超期秒数 = max(0, b - max(a, L + 168 小时))
学习奖励 = 扣费后净权益变化 - 0.10 × 超期秒数 / 3600
```

在每笔成交时刻分段求和。下单、撤单和结算均不重置时钟；回放期结束后的平仓成交不能消除期内超期。多个转移累加与整段账本积分必须相同，不在 rollout 边界重置。净权益奖励仍须独立望远镜求和到净盈亏。

积分惩罚不等于可行性证明：例如恰好到第 168 小时还未成交，超期时长积分为零，但端点硬验收仍失败。每 7 天至少一笔实际成交继续独立验收。

## 改善从何而来

对主成本、1 小时的**相同成交时刻与数量**逐笔拆分后，三个种子的均值为：

| 策略组 | 原始成交价盈亏 | 加减价损耗 | 手续费 | 净盈亏 |
| --- | ---: | ---: | ---: | ---: |
| 旧 PPO | +$0.124335 | $11.759756 | $3.810817 | −$15.446239 |
| 净权益重训 | −$0.014151 | $7.466071 | $2.472852 | −$9.953074 |
| 净权益 + 超期 | −$1.300809 | $7.092637 | $2.391124 | −$10.784570 |

恒等式为 `原始成交价盈亏 − 加减价损耗 − 手续费 = 净盈亏`（展示值四舍五入）。普通重训的改善主要来自成本损耗下降，原始成交价下的平均盈亏接近零，未显示新的预测优势。费用拆分并非把策略放到无成本环境重新决策，因此不能与上表无成本回放混同。

下一步应补充连续可交易的市场覆盖和可事前验证的事件信号，检查早于周频截止日的参与机会，再冻结新事件开发集进行比较。当前只有六个训练事件组、人工范围时间特征和假设成交成本；这些限制需要在正式收益评测前解决。

## 复现

已安装的可选 `sb3-contrib==2.7.1` 位于 `/tmp/foretellmesh-rl-deps`，其余锁定依赖在 `conda lab`。以下是本机路径；临时依赖目录需要保留。

```bash
export PYTHONPATH=src:tests:/tmp/foretellmesh-rl-deps
export MPLCONFIGDIR=/tmp/foretellmesh-mpl
conda run --no-capture-output -n lab python -m foretellmesh.trading_rl_retrain run \
  --dataset data/processed/pma_macro_research_20260919_v1 \
  --store data/processed/pma_macro_trade_store_20260919_v4 \
  --source runs/pma_allocation_ppo_v1 \
  --execution runs/pma_allocation_execution_lifetime_v1 \
  --config configs/allocation_ppo_execution_retrain_v1.json \
  --output runs/pma_allocation_ppo_execution_retrain_v1
conda run --no-capture-output -n lab python -m foretellmesh.trading_rl_retrain audit \
  --run runs/pma_allocation_ppo_execution_retrain_v1
conda run --no-capture-output -n lab python scripts/summarize_execution_costs.py \
  --run runs/pma_allocation_ppo_execution_retrain_v1
conda run --no-capture-output -n lab python -m unittest \
  test_trading_rl_env test_trading_rl test_trading_rl_diagnostic \
  test_trading_rl_execution test_trading_rl_reward test_trading_rl_retrain -v
```

已有输出目录拒绝覆盖；复现时另选空目录。`audit` 重放冻结权重而不重新训练，校验输入、动作、挂单、账本、权益曲线、统计及初始化与实际参数变化。`training_report.json` 单列真实步数、优化器、训练 episode 和参数变化。

## 适用边界

数据仍为 25 个 Polymarket 合约、6 个事件组、4,681 个小时转移。重复回放不增加独立事件。数据是事后核验已结算合约组成的研究集合；人工范围截止倒计时不是公开到期时间。成交价、假设的完整成交和成本不证明历史订单簿可执行性。4 小时迁移仍缺少显式挂单特征；终点净权益仍包含必要的延后结算，须报告其次数。

这轮检验交易决策层的学习机制，没有训练预测概率、8B 或任何 LoRA，也没有验证多 Agent 的增量收益。获得训练内改善后，仍需核实公开时间边界、冻结新事件开发集并建立更可靠的执行数据，才能进行新的样本外比较。
