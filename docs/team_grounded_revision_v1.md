# 围绕工具失败的自主研究修订 v1

本轮从结构化历史 v1 第一轮的真实失败继续：四个价格变量已成功绑定来源，但共同可用历史输入为 0，没有计算方案或评分。原运行与原始任务、提案、错误、工具检查和审核意见完整保留。本轮不是新的独立验证案例。

## 流程变化

1. 仍由团队查询目录并协商研究任务。协商完成后，程序按最终任务的精确合约 ID、已注册来源和研究截止时间重新查询目录，避免研究者继续使用旧任务的数据覆盖信息。刷新只返回数量、单位、时间、记录数等元数据；不增加来源，不返回价格值或标签，不决定采用哪种关系。
2. 历史记忆增加带原始反馈引用的工具事实，明确它们属于此前尝试，不是当前任务。新鲜度、初始化、缺失记录、共同覆盖等检查结果原样保留；已暴露的失败实验指纹纳入重复检查。
3. 学习上下文分别呈现 `tool_facts`、`candidate_hypothesis`、`reviewer_advice`。后两项仍为未验证模型内容。任务题材不同不是反证，模型审核不能代替工具观测。
4. 复盘增加 `diagnosis`：引用 1–4 个真实事实 ID，说明障碍及拟改变的内容。存在具体失败时，不能只引用泛化的工作流状态或审核意见。保留原 `next_task` 和缺失数据请求，下一轮实际执行团队选择的任务。

引用验证仅保证事实 ID 存在且触及失败，不会自动判定解释正确、方案有效或有预测优势。任务调整仍需通过合约绑定，变量与来源数量／单位匹配、滞后、初始化、新鲜度、联合样本、计算边界和评分前冻结等原检查。团队可自行缩小或更换合约、修改可检验关系、请求缺失数据或放弃，程序不预设策略类别或盈利公式。

初次目录查询、协商后的目录刷新和原始反馈均单独归档。目录边际覆盖不是共同可用样本，更不是成交可行性。查询截止时间为已注册研究截止时间；这些是离线训练设计信息，不回填到更早预测时点。

第一轮评估者建议释放原四个合约，协调者放弃。其理由笼统称合约“太旧、数据不足”，不能当作历史回放不可用的确定性结论：工具只证明原四变量组合在原时钟／滞后／新鲜度设置下没有共同输入，并未证明所有单合约历史都不可研究。

第一轮复盘提出缩小到 Chiefs 和 Argylle，确实移除了无记录的 Blast，但诊断只引用 Argylle、Saga 的非空边际覆盖，没有引用需回应的零覆盖事实；同时请求比特币价格和球队胜率，和下一任务的合约范围／测量身份没有明确对齐。一次修复逐字重复原 JSON，因此严格事实引用检查拒绝。这不等于证明其所有任务修改无用，只说明本协议要求的“失败依据—修订”关系没有被正确记录。失败的下一任务没有执行，第二轮由协调者重新选题。

第二轮选中两个电影合约、离婚合约和 Chiefs 合约，当前任务目录刷新成功。研究者提出以各自历史 Yes 价格预测各自结算结果，四个合约绑定齐全；这是四个单合约预测，并非发现了跨合约优势。

随后四个变量都把 `USD_per_YES_share` 同时写进 `quantity` 和 `unit`。实际注册测量应为：

| 字段 | 研究者声明 | 注册来源 |
| --- | --- | --- |
| quantity | `USD_per_YES_share` | `contract_yes_trade_price` |
| unit | `USD_per_YES_share` | `USD_per_YES_share` |

数据角色仍强行绑定 `pma_yes_trade_price`，初稿和一次修复完全相同，均被数量／单位检查拒绝。系统没有自动改写变量来迁就来源，也没有用别的量代替。

最后复盘正确引用 `source_measurement_mismatch`，但把声明不匹配解释为“来源缺测量”，并请求 `quantity=USD_per_YES_share` 的数据，重复了同一错误。已有来源本来就提供 Yes 价格；此次停止不能归因于缺少这种价格数据。正确引用错误日志没有带来正确诊断，亦没有形成可执行修订。预算结束后的建议只归档，没有继续执行或筛选更多结果。

## 下一步判断

此次已验证目录随当前任务刷新，以及事实引用机制能运作；尚未验证有效自主纠错、预测优势或盈利。改变参考失败、历史事实和复盘协议同时发生，不能把本轮与前轮的差异作为单因素改善证据。

接下来优先改善变量声明与修订接口：对已注册测量，让模型选择测量标识，程序展开其固定数量和单位，并保留模型选择记录；对真正新增的外部测量，仍允许自主声明并明确报告缺失，不能暗中替换成价格。以小规模冻结对照检验是否减少这类元数据错误，并是否能进入真实数值测试。任务题材、跨合约关系和研究假设仍由团队选择；这些执行问题本身不满足用户设定的微调条件。
