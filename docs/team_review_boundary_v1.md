# 研究审核权限边界 v1

本轮修正同一 Base 审核角色的权限：模型意见保留为未核实的研究质疑，不能因为不同题材、预测联系看起来不可信或审核输出格式失败，直接终止数据检验或强制研究者改写提案。

## 确定性检查与模型意见

新协议 `executable_review_boundary_v1` 显式启用；旧语义关卡、旧任务协商协议和已归档运行保持可复算。

- 任务协商和精确 ID 绑定不变；不能悄悄删掉指定合约。每轮预算和重复检查不变。
- 程序由结构化提案生成执行说明，固定实际目标合约、历史规则哈希、预测类型、输出单位、预测期限、输入变量和滞后，并校验合约初始化时间不晚于研究截止时间。
- 七天后 Yes 成交价与事件结算概率在执行说明中使用不同数量定义和单位，不从叙述文字猜测或替换类型。数据与计算角色接收这份说明。
- 数据源必须与声明的数量及单位精确一致；缺失保留缺失，不允许偷换价格代理。数据真实历史时间、初始化、滞后、陈旧程度、表达式范围、冻结后评分、事件组及时间规则仍由原程序检查。
- 模型审核仍使用原提示和 schema，以保留可比较的意见记录；所有 `aligned`、`mismatch`、`uncertain` 以及格式失败都不具有执行否决权。不再因审核意见触发强制语义改写。
- 固定语义案例继续记录，但仅用于诊断审核角色，不再授予或撤销执行许可。执行说明、原提案及审核内容都保存在尝试记录中。
- 学习角色明确区分模型意见与工具验证的错误；审核结果不能自动变成事实性经验或微调监督答案。

这里严格检查的是**声明和实际执行之间的对应关系**。程序不能据此保证任意自然语言叙述正确，也不能自动证明研究假设与所有历史规则语义一致。执行说明明确保留 `narrative_alignment_verified=false`；后续训练筛选通过仍只是训练数据上的结果，不能晋升策略或触发微调。关系是否有预测信息，需要冻结计算方法后用数据检验。

第一轮任务协商结果仍是三个合约。**其原始提案及语义审核内容与任务协商 v1 第一轮完全一致**，可在两个 `attempt_01.json` 中逐项比较。这次没有执行审核者要求的强制改写，而是让数据角色按原声明绑定来源。数据角色实际返回三个 `source_id=null`：比赛结果和两部电影的开画票房都没有匹配来源，程序遂以 `unavailable_variables` 停止。这与前述 CPU 边界回归一致，但这里是真实冻结模型轨迹。

因此，本轮确认的是权限变化生效：相同模型质疑不能再直接封杀假设；没有证明跨题材假设有预测优势，也没有因放宽审核而补造数据。第二轮复盘仍未形成新方法，重复检查正常拒绝它。

当前注册来源是历史 Yes 成交价。原提案却要求事件结果和票房，还把三种数量都写为 `quantity: "1"`；复盘数据请求仍把合约初始化时间用作历史时间要求。六条请求均未准入、没有触发下载或训练，不能把初始化时间当成数据发布日期。这里是具体声明与可用来源不匹配，不能等同于“数亿条历史成交数据没有价值”或整体数据量不足。

下一步建议先给团队提供可查询的数据目录及数量、单位、历史时间字段，让团队自主判断哪些问题可检验，再提出新假设。对确需外部数据的提案，应明确测量定义和发布时间，决定补源或暂存；不得为了通过检查把票房改叫成交价。此为后续实验建议，本轮没有自动更改研究者的数据可见性协议。
