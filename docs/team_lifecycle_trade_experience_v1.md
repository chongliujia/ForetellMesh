# 团队自主退出与逐笔交易经验

后续修复：原文中的在线经验准入已由 [事实核验与方法准入](team_fact_gate_v1.md) 加强；旧版格式合格记录不再直接进入当前决策记忆。本文实测结果保留原有含义。

## 行为与边界

新增 `team_lifecycle_v1` 可选执行路径。原有团队实验的默认执行接口、旧配置与保存的结果不变。团队能看到连续账户的现金、持仓、待执行订单和已实现盈亏，在原研究、工具、事件预测、风险审查后，再输出持仓决策：

- `buy`：申请入场；仍须经过预测意愿、风险否决、成本后优势、现金与敞口限制。
- `hold`：保留现金或已有仓位，取消该合约未成交订单。
- `sell`：绑定持仓编号，卖出全部持仓，明确最低卖价。无裸卖空、无自动反手。
- 结算：取消未成交买卖单，按结果兑付剩余份额，不生成虚假卖出成交。

卖出与买入都在实际生成延迟之后等待严格更晚的成交参考。第一条参考不满足限制则取消，不搜索后面的有利价格。同一时刻先处理结算，再处理成交。卖单只约束现有份额，不重复占用现金；入场、出场费用分别记一次。成交参考仍是假设全额成交的历史区块均价，不能证明真实订单簿深度或可成交性。

新增信号只在 `simulate(..., lifecycle=True)` 下接受。新接口保留 `Signal` 原位置参数，新增字段默认关闭；旧调用不增加协议统计字段。新的结果另报入场数、提前退出数、结算数与卖出成交额。

团队分别选择预测有效期、挂单期限、下次复核间隔。挂单期限从生成完成开始，受预测到期进一步限制；信号到期时不能成交。复核时间从观察时点开始，模型尚未完成时不能启动下一次调用。没有持仓上限天数、强制交易频率或固定止盈止损。

`run_window` 为有界实验调度器：复核固定准入合约集合中的未结算合约，按团队选出的时间刷新当时价格，保留原有已核验历史证据，不虚构期间新闻。复核次数与观察结束时间是计算预算，不是强制平仓时间。输出观察期账户，以及明确标记为“停止复核后剩余仓位持有至结算”的单独诊断账本。跨合约组合下单、自动增补新合约、外部事件触发复核尚未实现。

## 每笔交易都进入经验库

按一笔入场持仓建立一个经验编号，持续连接后续复核、提前卖出或结算。只要真实模拟入场成交就必须建档，盈利、亏损与盈亏为零均保留，不能只选盈利案例。未平仓的交易保留过程，结果为空；未成交订单与无效决策留在账户和调用日志中，不伪装成交易经验。

逐笔经验包含入场、出场、费用、净盈亏、持仓时长、事件组、原始团队决策和工具调查、源码对应的决策摘要哈希及执行假设。买卖两端归到同一持仓，避免把一次交易记成两个独立样本。

在训练模式中，每个新近可用的已结束交易都触发一次团队复盘，格式失败允许一次修复，仍失败则完整留痕。复盘给出判断评估，以及可为空的候选经验：适用条件、拟修改的方法、反证条件和下一项检验。经验的状态始终是“未验证假设”，不能因单笔盈利自动认定方法正确，或因单笔亏损直接认定概率错误。

有效经验在后续研究、预测、风险审查、持仓决策中可见，二元概率读出也显式接收经验。所有经验长期归档；单次模型上下文最多携带最近八条成功复盘，避免无限增长，不按收益筛选。当前实现不在每笔交易后微调模型。

时间隔离：提前退出只反馈已实现的交易结果，事件结果仍为空，不能提前计算事件 Brier；结算交易的监督反馈等待其 `available_at`，而不是把后来收集到的标签回填到过去。每条在线经验检查来源可用时间、复盘时间和内容哈希。已平仓交易后续事件预测评分可在独立评估层补充，当前提前退出复盘不会填造这项评分。

独立评估模式同样记录每笔经验，但不在线修改方法；训练模式只能用于训练分区。可以在训练中自主迭代，再冻结方法与记忆去做独立对照。当前模块不自动将经验晋级为 SFT 数据或已验证策略。

## 第一轮真实 Base 实测

`runs/qwen3_8b_team_lifecycle_trade_experience_smoke_v1` 完成，38 次调用可通过冻结源码在 CPU 上逐项重放。报告 SHA256：`9516c4c1c5c9a62c8617b48617bda246e427a997aad0b507efa2e0029917d2be`。

三次持仓复核只有一次完整有效。首条持仓输出截断，第三条试图卖出尚未持有的仓位，被校验拒绝。第二条有效决策后来产生一次入场。观察期内没有提前退出或结算，现金 $98.000002，另有一笔未平仓；不能把现金余额直接当成观察期净值。停止复核后的单独结算诊断为 $98.000002，净亏损 $1.999998；不等于团队自主提前退出后的表现。

九笔原账户交易全部建档、全部尝试复盘，只有三笔输出通过格式校验；失败包括截断、文本长度不合格与上下文超限，均保留，未补造答案。其中一条盈利复盘明确不给出新经验。其余候选也不能因格式正确就认定科学有效：例如“低概率事件一次盈利就反证低胜率”的说法不成立，单个结果不能检验概率校准。没有将这些候选升级为监督真值或已验证策略。

第二版 `configs/team_lifecycle_v2.json` 保留原计算预算，明确要求简短复盘文本，并将模型输入改为全部决策的概率、动作、检验摘要，加上入场和最后复核的详细证据。完整中间证据仍归档，摘要显式声明展示范围。九笔案例的输入在本地 tokenizer 下为 1991–7735 token，均留有 768 token 输出空间。这是格式与上下文接口修正，不是盈利方法优化。

## 第二轮结果与内容复核

`runs/qwen3_8b_team_lifecycle_trade_experience_smoke_v2` 完成，九笔交易全部获得格式合格的复盘，四笔提出候选经验、五笔没有提出新规则。两笔盈利、七笔亏损均被覆盖，没有按收益挑选案例。33 次模型调用及完整账本通过冻结源码的 CPU 重放；报告 SHA256：`651e367c8ae26ca702610dd132646abbb0eef9f5a4e3f6c27ff52de5999895b7`。一份冻结 Base 驻留 RTX 3090，运行约 3 分 13 秒，峰值分配显存约 17.10 GiB。没有训练、晋级或开启最终测试。

复盘格式成功不代表经验正确。内容复核发现：模型把 254462 和 504409 两笔亏损称为盈利；501858 的复盘混淆事件概率与价格变化，并误述成本归属。其他“数据不足就不交易”等候选也尚未形成经独立检验的有效方法。九笔逐项复核状态记录在 `runs/team_lifecycle_interface_review_v1/semantic_review.json`，全部未获监督数据准入。权威盈亏来自账本，不由模型复述决定。

持仓窗口仍为三次复核、一次有效完整决策、一次入场、零提前退出；因此本轮只证明执行机制和经验覆盖已接通，未证明 Base 已可靠掌握持仓管理。入场 `buy` 是交给现有概率/成本执行器考虑买入 Yes 或 No，不是自然语言理由中暗含方向的保证；理由与实际方向的一致性仍须审查。

109 项相关测试通过，包含 21 项新增生命周期/经验测试。另用当前代码只读重放原版 24 个决策，原来的九笔成交和 $106.523346 账户逐项相同，没有覆盖原实验文件。
