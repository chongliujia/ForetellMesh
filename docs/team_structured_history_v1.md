# 完整研究流程的结构化历史 v1

本轮将已完成的固定任务上下文对照接入两轮完整研究流程。共享 Qwen3-8B-Base 保持冻结，模型自主查询目录、协商任务、提出变量、绑定来源、设计计算和复盘；不人为规定跨合约关系或交易策略。

## 上下文与审计

新模式 `executable_structured_history_v1` 在每轮开始时投影此前的历史：保留失败状态、错误类别、实验指纹、缺失测量的数量和单位，以及确定性工具的覆盖和检验结果。当前角色的 `pending_task`、`original_task` 或 `active_task` 是任务依据，历史不是新指令。投影只使用本轮开始之前的调用和已完成尝试。

协商完成后，研究者收到最终任务、决定类别及协商记录哈希，不再重复阅读已被替代的任务正文与评估叙述。学习角色仍收到当前提案和工具结果，但原始错误回答改为错误类别及哈希，目录查询的旧任务理由也不重放。`feedback_sha256` 明确指向完整归档反馈，另用 `learning_view_sha256` 校验模型实际看到的投影。

每轮文件保留 `history_archive`、`history_view`、`learning_feedback_view`，以及原有完整协商、反馈、工作流和复盘；`calls.json` 保留所有请求、原文响应、修复、错误和耗时。单个角色的一次格式修复仍能看到自己的错误回答。没有删除失败，也没有将模型审核意见当成已验证事实。

此改动是上下文管理，不是参数学习。过去假设的自然语言不再反复进入研究提示，因而也可能损失有用细节；结构化错误、数据约束和指纹能保留什么，需要通过后续研究结果检验。旧实验模式和既有上下文对照的压缩函数保持原行为。

## 实验设计与复现

配置 `configs/team_structured_history_v1.json`：同一四合约失败任务起点、22 个准入训练合约、两轮预算、每次最多一次修复；模型、来源、评分时钟、联合输入检查、重复提案检查和评分前冻结均保持既有设置。新模式还投影协商和学习上下文，所以完整流程与上一版的差异不能解释为仅一处历史字段的固定输入因果对照。

```bash
PYTHONPATH=src python -m foretellmesh.team_research_loop preflight --config configs/team_structured_history_v1.json
PYTHONPATH=src python -m foretellmesh.team_research_loop run --config configs/team_structured_history_v1.json --output runs/qwen3_8b_team_structured_history_v1
PYTHONPATH=runs/qwen3_8b_team_structured_history_v1/source_snapshot python -m foretellmesh.team_research_loop audit --output runs/qwen3_8b_team_structured_history_v1
```

231 项回归测试通过。新增测试覆盖两轮流程、前轮历史边界、完整审计与投影哈希、反馈哈希引用、重复提案拒绝、查询失败、协商失败／放弃、缺失测量保留和精确调用复算。上一版数据目录运行的 13 次调用也通过当前代码兼容复算。以上包含合成测试，不能作为真实预测能力证据。

本轮不开放开发／最终测试集，不发起微调，不执行新交易。只有后续独立验证确认团队方法有效，才讨论模型微调。

还有一项明确失败：第一轮复盘的 `next_focus` 逐字采用审核意见中的一句“假设与体育目标不一致”，而没有处理确定性工具报告的共同覆盖为零。审核者依旧按题材分类质疑跨领域关系，这不是已验证的反证；本轮它没有程序否决权，却仍影响了学习角色的下一步建议。两轮结构合格的复盘不代表团队已学会有效纠错。

## 下一步

下一轮宜让团队先解释确定性失败，并核对其自主选择的变量／时间范围是否有可用历史，再提交修订任务或明确请求补数据。查询应跟随协商后的当前任务，避免只查询旧合约；团队可以保留跨题材假设、选择因果滞后或提出缺失数据需求，无须由程序预设策略。

同时将“工具观测事实”“模型审核建议”“拟验证假设”分别呈现给学习角色，检验下一步行动是否真的回应失败原因，而不是复述审核者意见。保留全部失败和自主选择，继续冻结 Base；当前尚无有效研究方法或独立改善证据，不进入微调。
