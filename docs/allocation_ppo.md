# 交易决策层 PPO 首轮实验

2026-09-20 已完成真实 PPO 优化、冻结检查点、历史验证回放及逐笔复算。**本轮尚未得到可替代固定规则的策略：三个种子在主成本假设下均亏损，且均未满足每 7 天实际成交的要求。** 不晋级默认策略，8B 权重与 LoRA 均未更新。

## 本轮训练了什么

训练的是独立的 **21,402 参数 MLP 交易决策网络**，采用 Maskable PPO；没有加载、训练或调用 Qwen3-8B，也没有运行新的多 Agent 推理。这一阶段只使用确定性历史量化特征，不能作为多 Agent、8B 或 LoRA 改善的证据。

- 数据：训练分区 46 条批准观测、25 个合约、6 个事件组；扩展为 2024-06-05 至 2024-12-17 的 4,681 个小时转移。重复回放不增加独立事件数。
- 输入：8 项账户特征，加 4 个候选槽位各 20 项市场/持仓特征，共 88 个浮点数。没有结算标签、未来价格、完整事件文字、绝对日期或市场 ID。候选身份只留在审计记录中。
- 动作：等待；对某个候选买 Yes/No、选择 $1/$2 预算；卖出一半或全部。共 25 个离散动作。候选范围有限，持仓优先入槽，再按当前信号或周频预计成本排序。
- 奖励：每步**扣费后清算价值近似的美元变化**。手续费与滑点已在账本计入，不重复扣费，不给下单或成交次数正奖励。整段奖励严格累加为最终净收益。
- 预测能力仍独立用 Brier 等评分。本轮优化的是交易决策，不是事件概率。
- 超过策略日历的残留仓位会请求退出；若仍无法成交，环境按审计结算结果结束。报告分别保留日历期末权益和最终现金；本次验证实际没有残留结算。

三个种子 7 / 17 / 27 各训练 32,768 步、7 个完整历史回放加下一段的 1 步。网络结构 `[64, 64]`，学习率 `3e-4`，每轮采样 1,024 步、batch 128、更新 4 epochs，gamma 0.995，GAE lambda 0.95，clip 0.2，entropy coefficient 0.01。使用 SB3 默认 Adam；检查点包含优化器状态，逐次优化指标写入 `seed_*/progress.csv`。

各种子参数更新 L2 范数分别约 **2.1683 / 2.2625 / 2.4596**，确认实际执行了梯度优化。全部只在 CPU 上训练，PyTorch 单线程。训练共 **83.17 秒**，24 组验证共 **58.42 秒**，含数据准备的整轮共 **168.33 秒**；GPU 与 8B 显存占用不适用。

依赖版本：Python 3.11.14、PyTorch 2.13.0、NumPy 2.2.6、Gymnasium 1.2.3、Stable-Baselines3 2.7.1、sb3-contrib 2.7.1。使用官方 [Maskable PPO](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html) 接口和 [Gymnasium 环境契约](https://gymnasium.farama.org/api/env/)。

## 共同执行规则及本轮修正

[环境实现](../src/foretellmesh/trading_rl_env.py)由 RL、初始化策略和固定规则共同使用。资金、成交、退出、候选筛选规则完全相同，因此不能把环境修正相对旧版的改善全部归给 RL。

1. 周频参与按预计往返成本排序；只允许较高价格一侧，且每份含假设成本小于 $1。**取消较高概率一侧太贵时转买极低概率一侧的逻辑**。周频买单预算限 $1。
2. 卖价减去假设滑点后非正时，取消退出指令并重试，不记录“零价成交”。未知盘口依然是数据缺口，没有假装已补齐历史价差。
3. 仍取决策后 300 秒内第一个原生成交区块作为假设全额成交参考；不跳过不利成交寻找更好的价格，不模拟缺失的订单簿队列或真实最小交易量。
4. 每个事件组成本敞口最多 $5、总敞口最多 $20；本版最多 4 个持仓，单笔最多 $2，因此实际持仓成本还受槽位限制。非周频普通开仓每日最多尝试两次。
5. 在持仓侧价格下跌 0.05、持有超过 48 小时（周频单 24 小时）或合约范围到期时，由共同执行层请求退出。真实模拟成交可能晚于退出请求；失败不会伪造平仓。
6. 每 7 天规则按实际买卖成交计时。第 6 天开始限制等待动作，提前尝试成交；当存在必须退出的持仓时也会由执行层请求退出。动作合法不保证存在后续成交。所有超期区间保留为失败，`policy_requirements_met=false` 阻止将该结果视为合格策略。

这一执行层只是提前尝试与验收门槛，**不构成有成交保证的约束优化算法**。本轮 RL 奖励没有另外加入周频违约成本；结果说明动作约束尚不足以使最终实际成交达标，需要在后续训练设计中验证约束可行性。

## 行为诊断

主成本下，PPO 种子 7 / 17 / 27 的持仓中位时长约 **4.02 / 2.99 / 2.97 小时**，各有 **26/42、29/42、31/44** 个头寸在 6 小时内平仓。固定均值回归的中位持仓约 49.04 小时（包含等待退出成交的时间）。PPO 的行为偏向较早退出，仍会支付往返成本；这些记录不能证明它识别了更准确的回归机会。

主种子 7 的唯一周频违约发生在 2025-02-13 04:30:38 UTC 至 02-20 11:32:11 UTC，间隔约 175.03 小时，超过上限约 7.03 小时。其他种子也保留了完整违规区间、缺失后续成交和价格上限取消统计。不能删除这些时段或仅报告无成本下较好的种子。

建议下一轮先在训练分区检查可成交机会和期限约束，补充更多独立事件及双侧报价，并加入成本约束的策略对照；参数与预算先冻结，再使用新的开发时段检验。暂不升级为 8B 的 LoRA/GRPO，也不在这批验证结果上反复搜索获利参数。

## 数据隔离与验证

[数据准备](../src/foretellmesh/trading_rl_data.py)严格校验分区哈希、事件组、合约历史不可变规则与逐时价格截断。只解析所请求分区的输入；历史规则审计中的结果字段在投影时去除。合约范围仍由初始化及最后一个批准观察时点确定。

训练前冻结配置、代码快照、训练特征和来源哈希。全部种子训练结束后写入 `training_report.json`，再读取验证市场价格和输入；验证特征冻结后才解析验证结算标签。训练合约和事件组与验证不重合，训练结算时间早于验证日历；最终测试不打开、不评分。

这仍是回顾性开发实验：标签在 2026 年归档，不能声称当时已有此数据集或策略；验证时段已被前面策略工作查看，也不是全新的未触碰测试集。已审计、已结算市场构成的候选集合存在选择偏差。

全仓库 **465 项测试：464 通过、1 项可选 GPU 测试跳过**。新增测试覆盖 Gym 契约、动作约束、部分退出、资金/成本账本、奖励累加、未来价格和标签隔离、周频实际成交、非正退出价、首次不利成交取消、训练/验证隔离、真实 PPO 梯度更新和篡改检测。冻结检查点重新计算全部 24 组动作、决策观测哈希、账本、奖励和指标。

## 复现

本机 `lab` 已有 PyTorch / Gymnasium / SB3，本轮只把额外的 sb3-contrib 放入 `/tmp/foretellmesh-rl-deps`，未改写 conda 环境。临时目录丢失时重新安装固定版本：

```bash
conda run --no-capture-output -n lab python -m pip install \
  --no-deps --target /tmp/foretellmesh-rl-deps sb3-contrib==2.7.1

PYTHONPATH=src:/tmp/foretellmesh-rl-deps MPLCONFIGDIR=/tmp/foretellmesh-mpl \
  conda run --no-capture-output -n lab python -m foretellmesh.trading_rl run \
  --dataset data/processed/pma_macro_research_20260919_v1 \
  --trade-store data/processed/pma_macro_trade_store_20260919_v4 \
  --config configs/allocation_ppo_v1.json \
  --output runs/pma_allocation_ppo_v1_reproduction

PYTHONPATH=runs/pma_allocation_ppo_v1/source_snapshot:/tmp/foretellmesh-rl-deps \
  MPLCONFIGDIR=/tmp/foretellmesh-mpl conda run --no-capture-output -n lab \
  python -m foretellmesh.trading_rl audit --run runs/pma_allocation_ppo_v1

PYTHONPATH=src MPLCONFIGDIR=/tmp/foretellmesh-mpl \
  conda run --no-capture-output -n lab python scripts/plot_allocation_ppo.py \
  --run runs/pma_allocation_ppo_v1

PYTHONPATH=src:tests:/tmp/foretellmesh-rl-deps MPLCONFIGDIR=/tmp/foretellmesh-mpl \
  conda run --no-capture-output -n lab python -m unittest discover -s tests -v
```

`pyproject.toml` 另提供 `rl` 可选依赖组；本次实验配置会检查实际依赖版本，避免静默改变训练框架。重跑使用新输出目录，保留本轮完整失败案例和原始结果。
