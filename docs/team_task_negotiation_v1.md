# 团队研究任务协商 v1

本轮补上研究者与协调角色之间的显式任务协商。上一轮连续遗漏指定合约，说明“收到错误”并没有自动变成任务调整；程序不能静默删掉合约，也不应迫使研究者编造联系来满足 ID 覆盖。

## 已冻结协议

入口配置：`configs/team_task_negotiation_v1.json`，模式 `executable_task_negotiation_v1`。一个共享、冻结的 Qwen3-8B-Base，最多两轮训练研究，不改模型、数据、评分时钟或交易参数。

从 `runs/qwen3_8b_team_semantic_consistency_v1/attempt_01.json` 的真实失败任务开始，而非重新抽取一个容易成功的任务。该来源 report SHA256 固定为 `678cfc2169f4515e33b0c68a321467c95387ee2ddbdc0adcb0739317e883fc20`；同时校验 attempt artifact hash、训练范围、确为绑定失败，以及尚未产生输入检查／评分结果。任务和具体错误在模型运行前注册。它是已暴露的训练经验，不是独立验证样本。

每轮流程：

1. 研究者阅读原任务、每个指定合约完整历史规则、训练目录索引及失败反馈。逐合约声明 `retain` 或 `release` 并解释理由，提出新任务或主动放弃。
2. 程序验证每个原合约都被逐项说明，保留／移除状态与提议 IDs 一致；新增 ID 只能来自已准入训练目录。题材距离不作为程序否决规则。
3. 协调角色作出一次 `accept_proposal`、`retain_original` 或 `abstain` 决定，并说明理由。接受时才替换任务；拒绝修订时仍严格执行原任务。无提案不能接受，但协调角色可明确保留原任务。
4. 程序记录原任务、提议、决定、最终任务、增删 ID、目标是否变化及哈希。按最终 IDs 重新提取完整规则，研究者必须使用全部且仅这些合约；不会悄悄容忍遗漏。
5. 接着执行既有语义审核、确切来源绑定、输入可用性、计算冻结和训练评分。协商失败或协调角色放弃，本轮即停止研究执行，但保留失败和复盘。下一轮依然消耗固定预算。

每轮只有一次协商；每次模型调用沿用最多一次格式修复。协商角色看不到标签、价格覆盖或可用数据源，不能为了迁就现有价格数据而替换研究变量。新的合约可根据索引提议，但协商接受不验证其全部语义，研究阶段仍须读取规则并审核。

上一轮三个固定语义检查案例在本轮重跑；控制案例及其预期答案不进入研究者上下文。审核通过只是暂定声明一致，协商成功也只证明任务有记录地变化，都不能作为收益、预测优势或自动微调依据。

## 审核意见也有错误，不能作为监督答案

本轮暴露了上一版审核关卡的限制。第一轮原假设明确声称体育结果（248881）与电影合约（251132、251306）存在正相关，但审核者将足球输入判为错配，主要理由是足球与票房不相关；另一条意见还声称假设没有提及该变量。原假设实际明确列出了体育事件及其 ID，因此不能把这些意见当成经核实的否决依据。

这不证明假设有效。提案仍把电影票房／预测市场含混地称为金融市场表现，用 `quantity: "1"` 声明测量，未充分解释如何生成七天后 Yes 价格预测。审核者也没有可靠地区分目标成交价与合约结算条件。这里同时存在作者表述问题和审核理由问题，不能把所有失败归因于数据不足，更不能把“不同题材”当成不存在潜在关系的证据。

三个机制正反例不足以验证审核器在新研究上的可靠性。本轮保持预登记协议及原始错误，不在看到结果后重写已有运行。此语义审核器仍是实验性、未验证的关卡，不应晋升为策略或训练样本的权威裁判。

下一步应单独检验审核边界：让确定性程序严格检查合约绑定、测量来源、单位和历史时点；将“相关性是否存在”交给预先冻结的数据检验，避免让同一模型的题材直觉提前否决探索。对于真正的目标或测量错配，要求可核验的具体对应关系，而不是笼统的“无关”。同时继续检查复盘是否真正改变提案，而非复制上一轮理由。

复盘共提出五条数据请求，但它们仍使用模糊的 `quantity: "1"`，时间要求沿用了合约初始化时间。初始化时间不是变量的发布日期；这些请求未经准入、未触发下载，也未成为训练监督。本轮没有任何预测效果或盈利改善结论。
